# AI 智能审核 V1 需求映射与实现状态

这份清单依据[完整需求对话](https://chatgpt.com/share/6abb4a1a-e22c-83ea-8256-11ad3bce997f)最后的《AI 审核平台领域模型与总体架构设计 V1》整理。它是实现验收清单，不把讨论中的建议写成已经具备的功能。状态截至 2026-09-29；`已实现`仅表示代码和本地自动化检查覆盖，真实 PostgreSQL 迁移联调仍需执行。

## 领域边界

| 需求                                    | 必须保持的关系与约束                                                                                         | 状态                                   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------ | -------------------------------------- |

| AuditTask 与 AuditRun                   | Task 是一项审核事项；每次执行生成新 Run，旧结果不可覆盖                                                      | 未实现                                 |

| FieldDefinition 与 CategoryFieldBinding | 标准字段独立版本化；类别绑定描述该类文档的抽取线索；Template 决定本次实际需要哪些字段                        | 未实现                                 |
| AuditTemplate 与 AuditPlan              | Template 是可复用、版本化的审核定义；Plan 是本次执行提案，校验后才能创建 Task/Run；临时规则留在任务内        | 未实现                                 |

## 开发验收顺序

1. **工作空间与配置所有权**：Project、Document、版本化 Field/Category/Template/Rule 的租户隔离与权限边界。
2. **证据可定位闭环**：上传 PDF/DOCX → 解析 → EvidenceNode → 原文 Viewer 高亮。先用真实样本验证复杂表格、扫描件和 DOCX 结构。
3. **抽参闭环**：指定字段 → 多路召回 → 提取 → 服务端证据核验 → Fact 状态与重试。建立抽取错误分类和可观察 Trace。
4. **审核闭环**：客观规则 → 主观规则 → Finding → 类型化结果与证据跳转；用双文档金额/主体一致性做端到端用例。
5. **运行与自动化**：Task/Run 状态机与快照、后台执行、进度、重跑；最后接 AuditPlan、Domain Tool 和 Agent 适配层。

每个阶段都需要真实文件样本、跨租户安全测试、数据库迁移与 API 集成测试。当前只实现了第 1 阶段中的 Project 基础切片，不能宣称具备审核能力。
