# `@jingwei/storage`

对象存储的技术端口及 S3 兼容实现。Audit 文档可通过这一实现连接独立运行的 RustFS；仓库不负责启动或管理 RustFS。

## 公共 API

### `StoredObject`

成功写入后的安全元数据：对象 key、content type 和字节数。它不包含供应商 bucket、内部 endpoint 或访问凭据。

### `ObjectStorage`

| 方法           | 语义                                             |
| -------------- | ------------------------------------------------ |
| `put`          | 以显式 key、字节和 content type 写入并返回元数据 |
| `get`          | 读取完整字节；不存在返回 `null`                  |
| `delete`       | 删除对象；实现应说明不存在时是否幂等             |
| `getSignedUrl` | 创建有界有效期的临时访问 URL                     |

## 所有权模型

业务模块拥有“附件属于谁、是否可下载、保留多久”等元数据和权限规则；storage 只拥有二进制对象机制。推荐流程：

1. 模块用例检查租户、主体和业务权限；
2. 模块生成不可猜测且带租户/模块前缀的 key；
3. 调用 `ObjectStorage`；
4. 在模块自己的表记录对象 key、业务归属和生命周期；
5. 下载前重新检查权限，再签发短期 URL。

不能把签名 URL 当作长期数据库字段或权限替代品。

## 实现要求

`S3ObjectStorage` 使用 AWS SDK v3、显式 endpoint 和 path-style 地址；支持写入、读取、幂等删除与最多 300 秒的 GET 签名 URL。内部地址与浏览器可访问地址可分开配置。Bucket 由运维预先创建；构造适配器不访问网络，`createApp` 不依赖对象存储在线。

Audit 当前限制每份文件为 20 MiB，并只接受 PDF/DOCX。上传经过服务端的租户、权限和文件头验证；业务数据库事务失败时尝试删除刚上传的对象。后续面向不可信生产上传时，还需要接入病毒扫描、隔离与定期孤儿对象清理。

新增适配器时应明确：

- 最大对象大小、允许的 content type 和流式策略；
- key 规范化与路径穿越防护；
- 服务端加密、TLS 和凭据来源；
- put 覆盖语义和条件写；
- delete 幂等语义；
- 签名 URL 的最大有效期；
- 多租户前缀与访问策略；
- 超时、重试和可观测性；
- 病毒扫描和隔离流程（用户上传场景）。

当前 `get`/`put` 使用完整 `Uint8Array`，不适合大文件。引入大文件前应扩展流式或分片契约，而不是把无限大小内容读入内存。
